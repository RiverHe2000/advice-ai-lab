# advicedoc · document intelligence for a financial-advice platform

Classify the documents that flow through an adviser platform (ten types: Statement of Advice,
Record of Advice, fact-find, Fee Disclosure Statement, ongoing fee consent, super member
statement, insurance schedule, authority to proceed, bank statement, correspondence), extract
what a Statement of Advice actually recommends (clients, adviser, date, risk profile, scope,
recommendations, fees, product replacements, authority signed), validate it deterministically,
route the uncertain documents to a human with a **calibrated** P(field correct), and reconcile
the advice against what the platform later shows — all measured against a synthetic corpus
with a known truth, with bootstrap intervals, paired tests and a simulator for every detector.

| | |
|---|---|
| Quality gates | `ruff`, `mypy --strict` (src and tests), **121 tests** (offline, CPU, ≈ 15 s, incl. Hypothesis properties, a real PDF round trip and a crash-and-resume of the workflow), **98 % branch coverage** |
| Corpus | 660 real PDFs (reportlab, byte-identical on re-run) with gold JSON: 120 SoAs of 4–8 pages in three layout styles, 60 of each other type, distractor content, a holdings snapshot per SoA with planted discrepancies |
| Models | TF-IDF + calibrated logistic regression classifier with an abstain threshold; `rules` / `llm` / `llm_validated` SoA extractors behind one protocol; a calibrated review router for selective prediction; one `ChatModel` protocol with scripted / OpenAI-compatible / in-process HF backends |
| Headline (CPU, deterministic) | Classifier **macro-F1 1.000** on 165 held-out documents (0.982 at 5 % OCR-like noise, 0.958 at 10 %), isotonic **ECE 0.001** vs sigmoid 0.064; rules extractor **120 / 120 SoAs exact** from the PDF text (field accuracy 0.60 at 5 % noise); reconciliation **57 / 57 planted discrepancies detected** with a measured 13 % false-alarm rate at a 5 % tolerance and 0 % at 10 %; validators + one re-ask per section lift the scripted-model extraction from 0.358 to 0.508 document accuracy at 30 % corruption (McNemar p < 0.001); the router reviews **31.7 %** of documents for **0 % residual error** on clean text and shows an honest 25 % → 14 %, 50 % → 3.3 % review-vs-residual curve on noisy text |
| Real models (one RTX 4070, 40 SoAs) | Qwen3-4B-Instruct-2507 zero-shot classifies the 165 test documents at **1.000** (ties the ML model, McNemar p = 1); as extractor it gets every scalar field right (field accuracy **0.945**, recommendations F1 0.982) and fails only on the two things validators cannot check — a boolean (authority signed, 0.45) and the replacement list (0.775) — so document accuracy is 0.725 and the **router reviews 27.5 % of documents for 0 % residual error** (ECE 0.002) where "review iff a validator fails" leaves 25.6 % residual. Qwen2.5-1.5B: 0 / 40 documents fully correct, recommendations F1 0.21, router needs 92.5 % review. Section 8 of [docs/RESULTS.md](docs/RESULTS.md) |

## 2. Architecture

```
 PDF ─► ingest (pdfplumber; OCR would plug in here) ─► Document(pages, lines, tables)
          │
          ├─► classify: TF-IDF + dense features ─► calibrated LR ─► label / abstain ─► metadata rules
          │
          └─► (SoA) extract ─┬─ rules: sections → tables/regex → fuzzy product master
                             ├─ llm: section prompts → JSON repair → pydantic → merge (bounded retries)
                             └─ llm_validated: llm + one targeted re-ask per failing section
                                   │
                                   ▼
                          validate (fee arithmetic, funds, products, replacements, dates, ABN, TFN)
                                   │
                                   ▼
                          route: P(field correct) per critical field ─► min < τ ? review : auto
                                   │
                                   ▼
                          reconcile against the platform holdings snapshot ─► per-client report
 workflow.py: SQLite jobs  received → classified → extracted → validated → routed → reconciled → done|failed
 api.py:      POST /documents · GET /jobs/{id} · GET /review · POST /review/{id} · GET /metrics · /health
```

| Component | File | Notes |
|---|---|---|
| Schema | `schema.py` | Pydantic models for the SoA extraction target, metadata gold, holdings snapshot; scalar fields optional so a partial extraction is typed and a `None` is a recorded miss, never a default |
| Corpus | `corpus/` | `products.py` (product master shared by generator, validators, extractors, reconciliation), `soa.py` (facts → gold → layout blocks), `templates.py` (nine other types), `layout.py` (styles, date/currency formats, text rendering), `render.py` (reportlab, invariant PDFs, font-metric column widths), `holdings.py` (simulator with planted discrepancies), `generator.py` (one seeded RNG per document, manifest) |
| Ingestion | `ingest.py` | pdfplumber words → lines by y-clustering, `extract_tables`; JSON dump/load; `load_many` cache; `apply_noise` seeded OCR-like corruption |
| Classifier | `classify/` | `features.py` (word + char TF-IDF on the first two pages + 36 dense values), `model.py` (`CalibratedClassifierCV`, abstain, joblib), `metadata.py` (labelled fields, letter address block, sign-off, first date), `zeroshot.py` (prompt with ten one-line definitions, repair, prose fallback, scripted responder), `evaluate.py` (bootstrap CIs, ECE table, abstain curve, noise, McNemar vs zero-shot, metadata accuracy) |
| Extraction | `extract/` | `sections.py` (exact then fuzzy headings, table attribution), `rules.py`, `llm.py` (seven `SectionSpec`s with schema examples, `ask_section` with bounded retries and feedback), `validated.py`, `fake.py` (gold-derived responder, seven corruption modes, fenced answers, re-ask fix probability) |
| Validators | `validate.py` | Pure functions → `Violation(code, severity, field, message)`; `section_of` maps a field to the section to re-ask |
| Router | `route/` | `features.py` (one record per critical field), `model.py` (standardise → LR → isotonic, GroupKFold by document, constant fallback), `evaluate.py` (risk-coverage curve, AURC, τ search, naive policies, reliability table, coefficients) |
| Reconciliation | `reconcile.py` | Expected positions from recommendations (aggregated per product), fuzzy holding match, four discrepancy kinds with tolerances, markdown report, evaluation against planted truth |
| Statistics | `stats.py` | Seeded percentile bootstrap, paired bootstrap with non-inferiority verdicts, exact McNemar, ECE with reliability table |
| Models | `llm.py` | `ChatModel` protocol: `FakeChatModel` (queue / rules / responder), OpenAI-compatible HTTP with bounded retries on 408/429/5xx and usage parsing, in-process HF (lazy torch import, hub id or local directory); `repair_json` (fences, prose, trailing commas, truncation) |
| Workflow | `workflow.py` | `JobStore` (SQLite jobs / transitions / corrections), `QueueBackend` protocol + `InMemoryQueue`, idempotent steps, retry cap, `stop_after` crash hook, review decisions stored as labelled corrections |
| API | `api.py`, `metrics.py`, `logging_utils.py` | FastAPI with request ids, upload limits, Prometheus counters and latency histogram on a private registry, log redaction of names / emails / phones / TFNs |
| CLI | `cli.py`, `config.py` | eleven sub-commands; every default is an `ADVICEDOC_*` environment variable; `--gate` flags exit non-zero |

## 3. Quick start

```bash
python -m venv .venv && source .venv/bin/activate        # .venv\Scripts\activate on Windows
pip install -e ".[dev]"                                   # add [hf] for a local model, [serve] for the API

# corpus with real PDFs, gold and holdings (660 documents, ~4 s)
advicedoc corpus generate --out data/corpus --n-per-type 60 --n-soa 120 --seed 7

# classifier: train on a stratified split, evaluate with noise, calibration table and a gate
advicedoc train-classifier --corpus data/corpus --out runs/classifier.joblib --calibration isotonic
advicedoc eval-classifier --corpus data/corpus --classifier runs/classifier.joblib \
  --out runs/classifier_eval --noise 0.05 0.10 --zero-shot --model fake --gate --min-macro-f1 0.95

# SoA extraction: rules vs scripted llm vs llm_validated with paired statistics
advicedoc eval-extraction --corpus data/corpus --strategies rules llm llm_validated \
  --model fake --corruption 0.3 --out runs/extraction
# ... or a real model behind any OpenAI-compatible endpoint (vLLM, Ollama, llm-gateway-release)
advicedoc eval-extraction --corpus data/corpus --strategies rules llm_validated \
  --model openai --model-name qwen3-4b --base-url http://localhost:8000/v1 --out runs/extraction_qwen
# ... or in-process
advicedoc extract data/corpus/soa/soa_0001.pdf --strategy llm_validated --model hf --model-name D:/models/Qwen3-4B-Instruct-2507

# review router and reconciliation
advicedoc eval-router --corpus data/corpus --strategy llm_validated --model fake --corruption 0.3 --out runs/router_eval
advicedoc eval-reconcile --corpus data/corpus --sources gold rules --tolerance 0.05 0.10 --out runs/reconcile
advicedoc reconcile --corpus data/corpus --doc-id soa_0007

# the durable workflow over an inbox, and the HTTP API
advicedoc run --inbox inbox --classifier runs/classifier.joblib --router runs/router.joblib --db runs/jobs.sqlite
advicedoc serve --classifier runs/classifier.joblib --router runs/router.joblib --db runs/jobs.sqlite --port 8080

make all        # ruff + mypy --strict + pytest (≈ 15 s)
make results    # regenerates docs/experiments (CPU stage ≈ 70 s; the GPU stage needs a model)
```

Every flag is also an environment variable (`ADVICEDOC_MODEL__KIND=openai`,
`ADVICEDOC_MODEL__BASE_URL=http://vllm:8000/v1`, `ADVICEDOC_STRATEGY=llm_validated`,
`ADVICEDOC_TAU=0.98`).

## 4. Design decisions

* **A corpus with a known truth, rendered as real PDFs.** The gold is written first and the
  document is rendered from it, so every number is a measurement, the PDF → text step is
  exercised for real, and the same seed gives byte-identical gold and PDFs. Layout variants,
  filler and distractors keep the classifier and the rules baseline honest.
* **Three extraction strategies behind one protocol, and the rules one is not a straw man.**
  On clean text it is exact and costs a millisecond; under OCR-like noise it collapses. The
  report keeps both rows because that is the real trade-off an LLM strategy has to win.
* **Missing is missing.** Section prompts, tolerant JSON repair, pydantic validation, one
  retry with the parse error explained, and then a recorded reason — never a silent default.
  Repairs, parse failures, retries and re-asks are counted and reported.
* **Validators are pure and typed; the re-ask is targeted and bounded.** Each hard violation
  names its field, which maps to one section; `llm_validated` re-asks that section once with
  the violation explained, and the report says how often that fixed it (44 / 58 at 30 %
  corruption).
* **The router is a calibrated probability, not a heuristic.** Selective prediction needs a
  ranking that is also a probability a reviewer can act on: out-of-fold isotonic calibration,
  an ECE table, and τ chosen from the risk-coverage curve for a stated residual-error target,
  compared against three naive policies with bootstrap intervals.
* **Detectors are evaluated against a simulator.** The reconciliation reports detection *and*
  false-alarm rates per discrepancy kind because the holdings simulator plants the truth; two
  simulator bugs surfaced that way and were fixed before the numbers were written.
* **Durable by construction.** The workflow persists every transition, each step is
  idempotent, a crash after `extracted` resumes from another process without re-extracting
  (tested), retries are capped, and reviewer corrections are stored as labelled examples. The
  queue is a protocol: `InMemoryQueue` here, a Pub/Sub adapter (subscriber pull → `get`, ack →
  `ack`, publish → `put`) is the production substitute and plugs in at `Workflow(queue=...)`.
* **OCR-agnostic.** Scanned documents would enter through an OCR layer (Google Document AI /
  Vision) that returns lines and tables into the same `Document`; the pipeline never depends on
  which OCR produced the text, and `apply_noise` measures robustness without one.
* **No PII where it does not belong.** TFNs never appear in the corpus and a TFN-shaped number
  in extracted text is a hard violation (the ABN's last nine digits pass the TFN checksum one
  time in eleven, so ABNs are masked first — found by a test); log lines are redacted.

## 5. Limitations (what was not done)

* The real-model stage (`scripts/run_experiments.sh` stage 2: zero-shot classification,
  `llm` / `llm_validated` extraction and the router on Qwen3-4B and Qwen2.5-1.5B) has not been
  run; every LLM number above is a mechanism check with a scripted model whose error rate we
  chose. Section 8 of `docs/RESULTS.md` says what the run produces and what it should cost.
* Clean-text accuracy of 1.000 for the classifier and the rules extractor reflects a templated
  corpus with three styles per type; it is not a claim about real licensee templates or scans.
* No Pub/Sub adapter, no object storage, no auth on the API, no retraining loop for the router
  from stored corrections (the corrections table exists; the loop does not).
* OCR noise is independent per character; real OCR errors cluster.

project reads *transactional* documents and turns them into typed records with a measured
error rate. `mlflow-model-lifecycle` (mlops-lab) governs a credit model's promotion; the two
small models here (classifier, review router) are built with the same calibration discipline
but live inside an application rather than a registry. Sibling projects: `../file-note-copilot`

[`genai-platform-lab`](https://github.com/ChuanHe-PhD/genai-platform-lab)

simulator with a known truth" method is the one from
[`mlops-lab`](https://github.com/ChuanHe-PhD/mlops-lab) (`model-monitoring-drift`);
[`llm-engineering-lab`](https://github.com/ChuanHe-PhD/llm-engineering-lab) is where the
serving and fine-tuning side lives.
